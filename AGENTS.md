# Repository Guidelines

## Project Structure & Module Organization

- `nodes/` contains the ComfyUI-facing node classes. Keep node metadata, input/output declarations, and thin `run()` adapters here.
- `utils/` contains implementation and reusable processing code. Group utilities by theme, such as `depth/`, `pcd/`, `meshes/`, `stereoscopic/`, and `videos/`.
- Place new nodes under `nodes/<theme>/` and their implementation under the corresponding `utils/<theme>/` path where practical. Nodes should call the utility implementation rather than duplicate it.
- `nodes/nodes.py` is the central registry for `NODE_CLASS_MAPPINGS` and `NODE_DISPLAY_NAME_MAPPINGS`.
- The root `__init__.py` exports the node mappings and declares `WEB_DIRECTORY` for ComfyUI.
- `web/` contains browser-side extensions and assets. `depthcrafter/` contains bundled DepthCrafter model support.
- `README.md` documents installation, available nodes, and user-facing behavior. Update it when nodes or their behavior change.

## Node Development Conventions

- Keep node classes focused on the ComfyUI interface: validate or adapt inputs, select the ComfyUI device or paths when needed, call a function from `utils/`, and return a tuple matching the declared outputs.
- Keep algorithms, tensor transformations, file-format handling, and other reusable processing in themed `utils/` modules.
- Follow the existing `TDGen...` naming convention for node classes and mapping keys. Use the `TDGen/...` hierarchy for `CATEGORY` values.
- Define ComfyUI metadata consistently: `INPUT_TYPES`, `RETURN_TYPES`, `RETURN_NAMES`, `FUNCTION`, `CATEGORY`, and `DESCRIPTION`. Add `OUTPUT_NODE` when the node has output-side effects.
- Register every completed node in both `NODE_CLASS_MAPPINGS` and `NODE_DISPLAY_NAME_MAPPINGS` in `nodes/nodes.py`. Keep mapping keys stable because saved workflows depend on them.
- Preserve ComfyUI datatype contracts, tensor shapes, dtypes, and device placement across the node/utility boundary. Make CPU/GPU transfers explicit when required by a library.
- Prefer relative imports consistent with neighboring modules. Avoid importing node modules from `utils/`; dependencies should flow from `nodes/` to `utils/`.

## Coding Style & Dependencies

- Use Python with four-space indentation and follow the style of nearby files. Keep modules focused and use type annotations when they clarify inputs, outputs, tensor shapes, or device handling.
- Use descriptive snake_case names for functions and variables and `TDGen...` PascalCase names for node classes.
- Do not hide expensive model loading, device transfers, or file writes in general-purpose helpers. Make these operations clear at their call sites.
- Avoid adding heavyweight Python, CUDA, or native-library dependencies unless they are necessary. Declare runtime dependencies consistently in `pyproject.toml` and `requirements.txt`, and document any manual system setup in `README.md`.
- Do not commit generated bytecode, environments, build artifacts, downloaded models, or local output files.

## Build, Test, and Validation

- No automated test suite, formatter, or linter is currently configured. Do not claim a check passed unless it was run in an environment with the required dependencies.
- Run `python -m compileall __init__.py nodes utils` for a basic syntax check.
- Run `pip install .` in the intended ComfyUI virtual environment to validate packaging and dependencies. Installation may require CUDA, PyTorch3D, PDAL, model packages, and other native prerequisites described in `README.md`.
- Start ComfyUI and confirm the package imports without errors, all changed nodes appear under their declared categories, and their inputs, outputs, and display names match the mappings.
- Exercise a targeted workflow for each changed node. Check output shapes and dtypes, CPU/GPU placement, saved paths or files, and model cleanup where applicable.
- For utility-only changes, prefer small deterministic checks that call the utility directly when its dependencies permit; then validate the calling node integration in ComfyUI.
- Run `git diff --check` before handing off changes.

## Change Hygiene

- Preserve unrelated working-tree changes. This repository may contain an active node/utility refactor, so inspect the current tree and diff before editing overlapping files.
- Keep changes scoped to the requested theme and avoid opportunistic restructuring.
- When adding or moving a node, update its themed node module, utility module, central mappings, dependency declarations if needed, and the README node overview as one coherent change.
- In change descriptions, report the validation performed and call out checks that could not run because ComfyUI, CUDA, models, or native libraries were unavailable.
